# Data contract: `web/data/*.json`

All files are UTF-8 JSON produced by `pipeline/export.py` and read by `web/app.js`.
Dates are `YYYY-MM-DD` (Asia/Taipei). Timestamps are ISO-8601 with offset.
Country keys are **ISO 3166-1 alpha-2, upper case**.

## Level codes

| level | zh | en | instruction zh | instruction en | colour (dark) | colour (light) |
|-------|----|----|----|----|----|----|
| 3 | 第三級：警告（Warning） | Level 3: Warning | 避免至當地所有非必要旅遊 | Avoid all non-essential travel | `#ff3b5c` | `#b3123a` |
| 2 | 第二級：警示（Alert） | Level 2: Alert | 對當地採取加強防護 | Practice enhanced precautions | `#ffb020` | `#d97a00` |
| 1 | 第一級：注意（Watch） | Level 1: Watch | 提醒遵守當地的一般預防措施 | Practice usual precautions | `#19ff8a` | `#1f8f5a` |
| 0 | 目前無針對性建議 | No specific advisory | — | — | `#0f1f17` | `#ece9d8` |

## `alerts.json`

```json
{
  "generated_at": "...",
  "levels": { "1": {"zh": "...", "en": "...", "instruction_zh": "...", "instruction_en": "..."}, "2": {}, "3": {} },
  "diseases": { "伊波拉病毒感染": {"zh": "伊波拉病毒感染", "en": "Ebola virus disease"} },
  "global": [
    { "disease": "新冠併發重症", "level": 1, "effective": "2023-11-01", "countries": 247 }
  ],
  "countries": {
    "CD": {
      "name_zh": "剛果民主共和國",
      "name_en": "Democratic Republic of the Congo",
      "max_level": 3,
      "alerts": [
        { "disease": "伊波拉病毒感染", "level": 3, "effective": "2026-05-27", "area_zh": "", "area_en": "", "iso_sub": "" },
        { "disease": "新型A型流感", "level": 2, "effective": "2026-09-01", "area_zh": "北京市", "area_en": "Beijing", "iso_sub": "CN-11" }
      ]
    }
  },
  "unmapped": [
    { "name_zh": "索馬利蘭共和國", "name_en": "Republic of Somaliland", "max_level": 1, "alerts": [ ] }
  ]
}
```

Rules:
- `alerts` sorted by level desc, then effective desc. Only **active** advisories (see ARCHITECTURE.md). Global advisories (same disease+level in ≥ 150 countries, e.g. 新冠併發重症 L1) are listed once in `global` with `applied_to_all: true` **and** applied to every country on the map except TW/AQ: each such row carries `"global": true` and counts toward `max_level`.
- `name_en` is the CSV `areaDesc_EN` cleaned (e.g. `Congo,Democratic Republic of the` → `Democratic Republic of the Congo` via `data/manual/country_names.json` override when present).
- `area_en` for sub-national rows comes from Gemini or `data/manual/areas.json`; fall back to `area_zh`.
- `diseases` contains every disease name appearing in `alerts.json` **and** `epidemics.json`.

## `epidemics.json`

```json
{
  "generated_at": "...",
  "window_start": "2024-10-08",
  "details_dir": "epidemics/",
  "items": [
    {
      "id": "tBYXtWARDQm_4vJR_H_4Hw",
      "date": "2026-10-07",
      "disease_zh": "流行性腮腺炎",
      "disease_en": "Mumps",
      "headline_zh": "美國-流行性腮腺炎",
      "headline_en": "United States – Mumps",
      "summary_zh": "加州聖地牙哥州立大學 9 月累計 14 例，校方提供免費追加劑。",
      "summary_en": "San Diego State University reported 14 cases in September; boosters are being offered.",
      "countries": ["US"],
      "area_zh": "美國",
      "area_en": "USA",
      "url": "https://www.cdc.gov.tw/TravelEpidemic/Detail/...",
      "ai": true,
      "has_full": true
    }
  ],
  "overviews": {
    "CD": { "zh": "近兩年剛果民主共和國…（≤3 句）", "en": "Over the past two years…", "items": 23, "updated": "2026-10-08" }
  }
}
```

Rules:
- `items` sorted by `date` desc, limited to the last **2 years** from run date.
- The full text (`description_zh` / `description_en`) is **not** part of this file (it was 61 % of its size and is only needed when an entry is expanded). `has_full` (boolean) is true when either description is non-empty; the text is lazy-loaded from `<details_dir><KEY>.json` (see below). `details_dir` is always `"epidemics/"`, relative to `epidemics.json`.
- `countries` = split of `ISO3166` by comma, trimmed, upper-cased; empty list for global/regional items. Items whose `areaDesc` starts with `全球` get `countries: []` and `global: true`.
- When Gemini is unavailable: `headline_en`/`summary_en` (and `description_en` in the details files) = zh text, `summary_zh` = first sentence of description, `ai: false`.
- `overviews` only for countries with ≥ 1 item; generated by Gemini from that country's items (title + summary list), zh & en.

## `epidemics/<KEY>.json`

One file per country key in `web/data/epidemics/`: `<ISO2>.json` for every alpha-2 that appears in any item's `countries`, plus `_global.json` for items whose `countries` is empty (global/regional). Compact JSON, UTF-8, keyed by `epidemics.json` item id:

```json
{
  "tBYXtWARDQm_4vJR_H_4Hw": { "zh": "原文…", "en": "Full translation…" }
}
```

Rules:
- A file contains **every** item that lists that country (an item with `countries: ["US","AU"]` appears in both `US.json` and `AU.json`; the duplication is intended so the UI fetches one small file per selected country).
- Items with empty `countries` appear only in `_global.json`.
- No file contains an id that is not in `epidemics.json` `items`; every item with `has_full: true` is present in each of its countries' files (or in `_global.json`).
- `zh`/`en` are strings; `en` falls back to the zh text when Gemini is unavailable.
- The exporter rewrites the directory every run and deletes any other `*.json` file in it, so countries that drop out of the 2-year window disappear.


## `epidemics-recent.json` (phone page news list)

Written by `pipeline/export.py` (`recent_epidemics`) next to `epidemics.json`: the items of the last 60 days, newest first, **the same objects as in `epidemics.json`** (full text still lazy-loaded from `epidemics/<KEY>.json`). Used by `m.html` so a phone does not download the two-year index.

```json
{ "generated_at": "2026-11-04T12:00:00+08:00", "days": 60, "since": "2026-09-05", "details_dir": "epidemics/",
  "items": [ { "id": "…", "date": "2026-11-03", "…": "same keys as epidemics.json items" } ] }
```

- `since` = run date − `days`; every item's `date` ≥ `since`. Checked by `python -m pipeline validate` (`check_epidemics_recent`): each item must equal the `epidemics.json` item with that id.

## `flights.json`

```json
{
  "date": "2026-10-08",
  "fetched_at": "...",
  "source": "https://www.taoyuan-airport.com/flight_timetable?lang=en",
  "hub": { "iata": "TPE", "name_en": "Taiwan Taoyuan International Airport", "name_zh": "臺灣桃園國際機場", "lat": 25.0777, "lon": 121.233 },
  "routes": [
    { "iata": "NRT", "city_en": "Tokyo (Narita)", "city_zh": "東京(成田)", "country": "JP", "lat": 35.7647, "lon": 140.386,
      "departures": 14, "arrivals": 13, "airlines": ["CI", "BR", "JL"] }
  ],
  "totals": { "departures": 420, "arrivals": 415, "destinations": 98 }
}
```

Rules:
- One entry per airport (IATA). `country` from `airports.json`. Entries lacking coordinates are dropped but counted in `totals.unmatched`.
- If fetch fails, the previous day's `flights.json` is kept and `meta.sources.flights.ok=false`.

## `world.json`

TopoJSON (`world-atlas` 50m) with `objects.countries`; every geometry has `id` = ISO alpha-2 (string) and `properties.name` (English). Geometries without an alpha-2 keep their numeric id prefixed `n`. Built by `pipeline/build_geo.py` from `world-atlas` + `world-countries` (ccn3 → cca2).

## `world-110m.json`

Same structure and id mapping as `world.json` but built from `world-atlas` `countries-110m` (≈ 106 KB vs 743 KB); used for narrow screens. Built by `pipeline/build_geo.py`.

## `airports.json`

```json
{ "NRT": { "name": "Narita International Airport", "city": "Tokyo", "country": "JP", "lat": 35.7647, "lon": 140.386 } }
```
From OpenFlights `airports.dat`, IATA-keyed, only airports with a 3-letter IATA code. Country converted to alpha-2 via `world-countries`.

## `countries.json`

```json
{ "JP": { "zh": "日本", "en": "Japan", "lat": 36.2, "lon": 138.25 } }
```
Name lookup for every ISO alpha-2 (zh from `world-countries` `translations.zho`, with `data/manual/country_names.json` override), centroid for label/arc placement.

## `places.json` (search: airports and cities)

Written by `pipeline/places.py` during `export_all` (and re-exported idempotently: an unchanged list keeps its `generated_at`). Used by the search boxes of `index.html` and `trip.html` (`web/js/places.js`), which load it together with `airports.json` the first time a search box is used — never at page load.

```json
{ "version": 1, "generated_at": "2026-11-04T12:00:00+08:00",
  "places": [ { "code": "NGO", "iso": "JP", "zh": "中部", "en": "Chubu Centrair Intl",
                "alias": ["名古屋", "中部國際", "セントレア", "Centrair", "Nagoya"] },
              { "code": "", "iso": "TH", "zh": "曼谷", "en": "Bangkok" } ] }
```

- `code`: IATA airport code, or `""` for a city without one. `iso`: country (alpha-2) the search opens. `zh`: never empty. `en`: may be `""`.
- Airports with a Chinese name, from (first that applies) the TDX airport list (`airports_tdx`), `pipeline/airport_zh.json`, the TPE routes (`flights.json` `city_zh`) and the outbreak route watch (`watch.json`). A name that is just a country's name (TDX calls OVB Novosibirsk "俄羅斯") gives way to another source when there is one; single-airport places keep it (HKG 香港).
- `alias` (optional, airports only): other names the airport answers to in search — the Chinese names of the sources above that lost to `zh` (not a country's name), then the hand-kept list `pipeline/airport_alias.json` (city, nickname, local spelling: NGO → 名古屋, Nagoya, セントレア). No repeats of `code`, `zh` or `en`. An airport with no Chinese name in any source takes the first Chinese name of that list (FKS 福島).
- Cities: the CWA forecast cities (`weather.json`).
- Every other airport is searchable by English name, city and IATA code through `airports.json`; the page also lets an airport answer to the Chinese name of its city when that city is in this file (曼谷 → BKK, DMK). The arrivals board's flight search uses the same names for the origin airport (名古屋 → flights from NGO).
- `python -m pipeline validate` checks it (`check_places`): IATA or empty code, ISO-2 country, non-empty `zh`, `alias` a list of up to 24 short names, no HTML.

## `arrivals.json`

Inbound international passenger flights per Taiwan airport / quarantine checkpoint for the arrivals board. Unlike the files above it is **not** written by `pipeline/export.py`, **not** committed (`.gitignore`), and is published straight to GitHub Pages by `.github/workflows/arrivals.yml` every ~10 minutes (`python -m pipeline arrivals`, built by `pipeline/arrivals.py`). The page must treat it as optional: it can be absent (fresh deployment, no TDX credentials) or older than the other data files.

**The authoritative contract (fields, window, codeshare/checkpoint/status rules, usage counters) is `docs/ARRIVALS.md`.** Summary: `generated_at`, `source` (`tdx` | `tdx-anon`), `endpoint`, `tdx_updated`, `window` (`generated_at − 2 h … + 4 h`), `refresh_minutes`, `quota` (call counters carried between runs), `airports` (Taiwan airports with short zh/en names, coordinates, in-window flight count, TPE checkpoints A–D), and `flights` (sorted by best time; times `YYYY-MM-DDTHH:MM+08:00`; origin `lat`/`lon` or `null`). `python -m pipeline validate` checks it when present (`pipeline/validate.py: check_arrivals`).

## `watch.json` (outbreak route watch)

Direct-flight networks of outbreak cities, drawn on the map when switched on in the header menu 「疫區航線」.
Built by `python -m pipeline watch` (also at the end of every `export`) from hand-maintained inputs in
`data/manual/watch/`: one `<id>.json` (hub, titles, reason, source, `as_of`, country-name → ISO map, coordinate
overrides) plus the routes CSV it names (`Country,City_Airport,IATA,Monthly_Flights,City_zh`; the aliases `City`, `Code`,
`Flights_Per_Month` are accepted). Optional `notes` `{IATA: {zh, en}}` flag destinations such as one with a reported
exported case (→ `note_zh` / `note_en` on that route, drawn with a red warning ring). No timestamp, so the
file only changes when the inputs do.

```json
{ "sets": [ {
  "id": "irkutsk", "hub_zh": "伊爾庫次克", "hub_en": "Irkutsk",
  "title_zh": "…", "title_en": "…", "reason_zh": "疑似鼠疫疫情", "reason_en": "Suspected plague outbreak",
  "source_zh": "FlightConnections（…）", "source_en": "FlightConnections (…)", "source_url": "https://www.flightconnections.com/", "as_of": "2026-10",
  "hub": { "iata": "IKT", "country": "RU", "lat": 52.268, "lon": 104.389 },
  "routes": [ { "iata": "OVB", "city_en": "Novosibirsk", "city_zh": "新西伯利亞", "country": "RU",
                "lat": 55.0126, "lon": 82.6507, "monthly": 176 } ],
  "totals": { "destinations": 51, "monthly": 1568, "countries": 7 }
} ] }
```

Route lists come from FlightConnections (<https://www.flightconnections.com/>); `source_url` (optional, https only) is
shown as a link in the menu. Rules: `routes` sorted by `monthly` desc (routes listed with `monthly: 0` are kept and drawn faint); coordinates from `airports.json`, else the set's `coords` override
(`[lat, lon]`); a route without coordinates is dropped with a warning. To add or retire a watch, add/remove the
`<id>.json` + CSV pair (or set `"enabled": false`) and run `python -m pipeline watch`. Deep link: `?watch=<id>`.


## `weather.json` (world-city forecast)

Central Weather Administration open data **F-C0032-007 全球都市天氣預報**: 80 cities, 7 daily forecasts each. Built by
`pipeline/weather.py` from `data/raw/cwa/F-C0032-007.json` (file API, JSON). `update-data.yml` downloads it twice a day with
the `CWA` repository secret (env `CWA_API_KEY`; the key is passed as a URL parameter and masked in every logged error); without
a key, or when the download does not parse with ≥ 50 cities, the previous raw file is kept and re-exported. The dataset is
Chinese only: English names, ISO country and coordinates come from `data/manual/cwa_cities.json` (keyed by `StationID`, a WMO
station number); stations missing there are still exported (empty `name_en`, `iso: null`) and listed under `unmapped`.

```json
{
  "generated_at": "2026-10-30T16:20:00+08:00",
  "source": { "dataset": "F-C0032-007", "url": "https://opendata.cwa.gov.tw/dataset/forecast/F-C0032-007",
              "issued": "2026-10-30T08:00:00+08:00", "fetched_at": "…", "ok": true },
  "regions": [ { "id": "asia", "zh": "亞洲、大洋洲", "en": "Asia & Oceania" }, … ],
  "days": [ "2026-10-31", …7 ],
  "cities": [
    { "id": "47662", "name_zh": "東京", "name_en": "Tokyo", "iso": "JP", "region": "asia", "lat": 35.69, "lon": 139.69,
      "days": [ { "date": "2026-10-31", "wx_zh": "多雲", "wx_en": "Cloudy", "code": "04", "icon": "cloud", "max": 24, "min": 14 }, … ] }
  ],
  "unmapped": []
}
```

- `regions` keep CWA's own grouping and order (CWA lists e.g. Moscow and Istanbul under 亞洲、大洋洲).
- `days[].date` is the Taiwan calendar date (UTC+8) of the 24-hour period CWA forecasts, not the city's local date.
- `icon` ∈ `sun, partly, cloud, overcast, rain, showers, thunder, snow, sleet, fog`, derived from the Chinese phrase
  (thunder > snow/sleet > showers > rain > fog > sun/partly > overcast > cloud) so new CWA codes still get an icon; `wx_en`
  comes from a phrase table in `weather.py`, falling back to the icon's name. `max`/`min` are integer °C or `null`.

## `travelmed/<ISO>.json` (travel prescription page text)

One file per country whose CDC web page has been read (`countries[ISO].page` in `travelmed.json`); loaded when its card opens.

```json
{
  "iso": "TH", "cid": "498", "zh": "泰國", "en": "Thailand", "checked": "2026-11-05",
  "url": "https://www.cdc.gov.tw/Internationaltravel/Index/ZkNLTkRxQ0NyQmc5Rk50dmZZZlI2Zz09",
  "page": {
    "sections": {
      "before":   [ { "t": "孩童和成人的免疫狀態不同…", "d": 1, "k": "建議諮詢旅醫門診", "g": "infants" }, … ],
      "vaccines": [ { "t": "大部分疫苗接種後需要2週才會產生足夠保護力…" } ],
      "diseases": [ { "t": "預防蚊蟲叮咬", "h": 1 }, { "t": "日本腦炎、瘧疾…", "k": "重要流行疾病" }, { "t": "…", "d": 2 }, … ],
      "during":   [ … ], "after": [ … ]
    },
    "vaccines": [ { "name": "黃熱病疫苗", "lines": [ { "k": "入境預防接種規定", "t": "…" }, { "t": "…", "g": "pregnancy" }, … ] } ],
    "hotline": [ { "where": "", "tel": "+66-81-666-4006" } ]     // Taiwan missions' emergency lines; Vietnam: 河內, 胡志明市
  },
  "subs": [ { "cid": "…", "zh": "葡屬亞速群島", "en": "Azores", "checked": "…", "page": { … } } ]
}
```

- A line: `t` plain text (never HTML); optional `d` list depth 1–4, `h` 1 = sub-heading, `k` bold label shown before `t`,
  `g` traveller group ∈ `infants, pregnancy, chronic, immuno, longstay, aid` (shown only when the traveller picks it).
- Section keys ∈ `before, vaccines, diseases, during, after`; any may be missing. `hotline` may be empty (no Taiwan
  mission there); `where` names the mission's city when there are several, else `""`.
